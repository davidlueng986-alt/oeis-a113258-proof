# Lean 4 formalization of the A113258 proof

`A113258.conjecture_false : ¬ ∃ n > 4, ∃ b > 1, ∃ e > 1, a n = b ^ e`

This is the negation of the statement `OeisA113258.conjecture` in
[google-deepmind/formal-conjectures](https://github.com/google-deepmind/formal-conjectures/blob/main/FormalConjectures/OEIS/113258.lean);
`a` is defined exactly as there.

## What is and is not machine-checked

`#print axioms A113258.conjecture_false` lists, besides `propext`, `Classical.choice` and `Quot.sound`:

1. **`A113258.laurent_cor2` (an axiom, not proved).** A specialisation of M. Laurent, *Acta Arith.* **133** (2008) 325–348, Cor. 2 (constants `(m, C) = (10, 25.2)`, as quoted in arXiv:2604.18991). It is stated in `A113258/Laurent.lean`.
2. **Two `native_decide` axioms** for the finite certificate table (`A113258/CertCheck.lean`). They trust Lean's compiler and evaluator for the executable checker in `A113258Check/Checker.lean`, not just the kernel. The soundness of that checker is proved in `A113258/Cert.lean` and `A113258/CertCore.lean`.

Everything else is proved in Lean/Mathlib, with no `sorry`: the elementary lemmas (`Elementary.lean`), the real-number estimates (`LaurentNumerics.lean`), the reduction to Laurent's bound (`Laurent.lean`), the cases n = 5, 6 (`Small.lean`) and the final assembly (`Main.lean`).

So this is a Lean check of the whole argument **relative to** Laurent's theorem and to the Lean compiler for the table check. It is not an axiom-free formalization.

## Build

Lean `v4.36.0`, Mathlib `v4.36.0` (see `lean-toolchain`, `lake-manifest.json`).

```bash
cd lean
lake exe cache get      # prebuilt Mathlib
lake build              # about 5 minutes extra for the native_decide table check
lake exe check          # optional: the same table check as a native program (about 4 minutes)
```
